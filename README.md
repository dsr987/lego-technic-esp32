# Lego Technic ESP32 — моторизация с веб-управлением

Прошивка для контроллера ESP32, превращающая модели Lego Technic в управляемую со смартфона технику. Плата сама поднимает Wi-Fi точку доступа, управление идёт из обычного браузера: без приложений, роутера и интернета.

Проект развивает идею единой универсальной платформы электроники для любых моделей Lego.

Текущая версия прошивки: **0.0.6** | [Техническая спецификация](project_logic.md)

---

## Основные возможности

- **Два режима управления**, переключаются в интерфейсе на лету, выбранный режим запоминается после перезагрузки:
  - **Танковый:** два независимых слайдера для левого и правого борта.
  - **Классический:** основной привод (мотор A), руль (сервопривод) и дополнительный мотор B для кранов, лебёдок и дамперов.
- **Web-интерфейс:** тёмная тема, вёрстка под горизонтальный экран телефона, схемы техники, сброс слайдеров в ноль при отпускании. Внешние ресурсы (CDN) не используются, страница полностью хранится в плате.
- **Калибровка руля из браузера:** смещение центра (trim) и максимальный угол (maxdeg), значения сохраняются в энергонезависимой памяти платы.
- **OLED-дисплей:** режим, заряд батареи (проценты и вольты), число подключённых клиентов, иконка режима.
- **Защита:**
  - программный watchdog: если 500 мс нет команд, моторы останавливаются, а серва возвращается в центр;
  - полноэкранное предупреждение LOW BATTERY при напряжении ниже 6.0 В.
- **Обновление по воздуху (OTA):** прошивка с телефона через страницу ElegantOTA (`/update`), разбирать модель не нужно.

## Аппаратная часть

### Компоненты

| Компонент | Назначение |
| --- | --- |
| **ESP32-WROOM-32** | Микроконтроллер |
| **TB6612FNG** | Двухканальный драйвер DC-моторов |
| **Lego Technic L / XL** | Приводные моторы |
| **Geekservo 360° / SG90** | Рулевой сервопривод или вспомогательный механизм |
| **OLED SSD1306 (I2C)** | Дисплей 128x64 |
| **Mini360 DC-DC** | Понижающий преобразователь (5 В) для ESP32 и сервы |
| **BMS 2S (10 А) + 2× 18650** | Аккумуляторный блок (7.4 В) |
| **Делитель 100 кОм / 39 кОм** | Измерение напряжения батареи |

### Подключение (GPIO)

| Назначение | GPIO | Назначение | GPIO |
| --- | --- | --- | --- |
| TB6612 STBY | 4 | TB6612 BIN1 / BIN2 | 19 / 21 |
| TB6612 AIN1 / AIN2 | 16 / 17 | TB6612 PWMB | 22 |
| TB6612 PWMA | 18 | Сигнал сервопривода | 27 |
| OLED SDA / SCL | 25 / 26 | Замер напряжения (АЦП) | 34 |

> **Примечание:** пины с загрузочными функциями (GPIO 0, 2, 5, 12, 15) и линии флеш-памяти намеренно не используются, чтобы исключить сбои при старте.

### Питание

Аккумуляторы → BMS → выключатель → общая шина. С шины питаются Mini360 (5 В для ESP32 и сервы) и вход VM драйвера TB6612. Все GND сводятся в одну точку.

## Сборка и прошивка

### Окружение

Нужен **ESP32 Arduino Core 2.0.9**, версию менять нельзя:

- в коде используется классический API `ledc` (`ledcSetup`, `ledcAttachPin`), который на ядре 3.x изменён;
- библиотека `ESPAsyncWebServer 3.1.0` на ядре 3.0.2 и новее не компилируется (ошибка `ets_printf`).

Библиотеки:

- `ESPAsyncWebServer` 3.1.0
- `AsyncTCP` 1.1.4
- `ArduinoJson`
- `Adafruit SSD1306`, `Adafruit GFX Library`, `Adafruit BusIO`
- `ESP32Servo`
- `ElegantOTA` (один раз в файле `ElegantOTA.h` заменить `#define ELEGANTOTA_USE_ASYNC_WEBSERVER 0` на `1`)

Плата: **ESP32 Dev Module** (`esp32:esp32:esp32`).

### Первая прошивка (USB)

Arduino IDE: откройте `lego_technic_esp32/lego_technic_esp32.ino` (вкладка `app.cpp` появится рядом), выберите плату и загрузите.

Или через `arduino-cli`:

```
arduino-cli compile --fqbn esp32:esp32:esp32 lego_technic_esp32
arduino-cli upload -p COM3 --fqbn esp32:esp32:esp32 lego_technic_esp32
```

(вместо `COM3` подставьте свой порт).

### Обновление по воздуху (OTA)

1. Внесите изменения в `app.cpp` и сделайте commit. GitHub Actions сам соберёт прошивку (вкладка **Actions**, около 3–6 минут, ждите зелёную галочку).
2. Откройте раздел **Releases**, выберите последний релиз (`build-N`) и скачайте файл `lego_technic_esp32.ino.bin`. Делайте это до подключения к плате: у её точки доступа нет интернета.
3. Подключитесь к Wi-Fi платы (по умолчанию `LegoTechnic`).
4. Откройте `http://192.168.4.1/update`, авторизуйтесь и загрузите `.bin`. Плата перезагрузится сама.

Номер релиза (`build-N`) выдаёт GitHub, версия прошивки указана в шапке `app.cpp`. Это разные вещи.

## Настройки по умолчанию и безопасность

| Параметр | По умолчанию | Где менять |
| --- | --- | --- |
| Имя Wi-Fi точки | `LegoTechnic` | `app.cpp`, около строки 655: `WiFi.softAP("LegoTechnic", "12345678");`, первый аргумент |
| Пароль Wi-Fi точки | `12345678` | там же, второй аргумент (не короче 8 символов) |
| Логин и пароль OTA | `admin` / `admin` | `app.cpp`, около строки 671: `ElegantOTA.begin(&server, "admin", "admin");` |

Номера строк приблизительные, надёжнее искать по тексту `WiFi.softAP` и `ElegantOTA.begin`.

После смены значений перепрошейте плату, а на телефоне «забудьте» старую сеть и подключитесь заново.

**Внимание:** значения по умолчанию публичны, потому что репозиторий открытый. Тот, кто знает пароль точки доступа и OTA-логин, может управлять моделью и перепрошить её. Смените оба значения, если модель используется вне домашней мастерской, например в школе или на выставке.

## Известные особенности

- **Ток моторов.** TB6612FNG рассчитан на 1.2 А на канал постоянно (пик 3.2 А). Lego-моторы, особенно XL, при заклинивании потребляют больше. Не держите механизм в упоре под нагрузкой.
- **Остановка мотора = выбег.** При нулевой скорости на драйвер подаётся Stop (выходы отключены), мотор не тормозит. Лебёдка или кран с грузом при нуле груз не удержат.
- **Geekservo 360° — серва непрерывного вращения.** Ширина импульса задаёт скорость, а не угол. «Максимальный угол» для неё означает предел хода до механического упора. Для точного рулевого управления нужен позиционный сервопривод (например, SG90).
- **Помехи.** При сборке на постоянной плате поставьте конденсатор 470–1000 мкФ по питанию драйвера (VM/GND) и сведите все земли в одну точку.
- **Замер батареи** откалиброван под конкретные резисторы (`BATT_DIVIDER_FACTOR`). При замене резисторов пересчитайте: новый = старый × (показание кода / показание мультиметра).
