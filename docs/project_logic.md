## 1. Назначение и архитектура

Проект управляет моделью LEGO Technic на ESP32-WROOM-32. Контроллер создаёт собственную Wi-Fi точку доступа; управление выполняется из браузера через Web GUI и WebSocket. HTTP обслуживает интерфейс, диагностический журнал и ElegantOTA.

Основные части:

- шесть моторных каналов A–F;
- рулевой сервопривод S;
- позиционный LEGO Power Functions Servo на канале C с аналоговой обратной связью;
- OLED SSD1306 128×64;
- мониторинг напряжения батареи и Wi-Fi;
- сохранение настроек в NVS через `Preferences`;
- OTA-обновление через ElegantOTA;
- диагностический журнал Serial с доступом по HTTP.

### Текущая конфигурация моторных драйверов в main

| Логический канал | Физический драйвер | Физический выход | Роль |
|---|---|---|---|
| A | Adafruit Motor FeatherWing V2, PCA9685 + TB6612FNG | M1 | DC-мотор |
| B | Adafruit Motor FeatherWing V2, PCA9685 + TB6612FNG | M2 | DC-мотор / имитация ДВС |
| C | Отдельный TB6612FNG, напрямую от GPIO/LEDC ESP32 | Канал A моста | Модифицированный позиционный PF Servo |
| D | Отдельный TB6612FNG, напрямую от GPIO/LEDC ESP32 | Канал B моста | DC-мотор |
| E | Adafruit Motor FeatherWing V2, PCA9685 + TB6612FNG | M3 | DC-мотор |
| F | Adafruit Motor FeatherWing V2, PCA9685 + TB6612FNG | M4 | DC-мотор |

Таким образом, текущий код использует четыре канала FeatherWing (A/B/E/F) и два канала отдельного TB6612FNG (C/D). Это не схема «два прямых TB6612FNG для A–D» из старой Hardware 1.5.

FeatherWing управляется официальной библиотекой Adafruit Motor Shield V2.4, указанной в комментарии к прошивке как Adafruit Motor Shield V2 Library 1.1.4. Backend находится в `i2c_motor_backend.cpp`.

## 2. Распиновка ESP32

Единственный источник истины для GPIO — `lego_technic_esp32/hardware_config.h`.

| Сигнал | GPIO | Назначение |
|---|---:|---|
| `TB_STBY` | 25 | STBY отдельного TB6612FNG, каналы C/D |
| `TB_AIN1` | 18 | Направление C, вход AIN1 |
| `TB_AIN2` | 19 | Направление C, вход AIN2 |
| `TB_PWMA` | 23 | PWM C |
| `TB_BIN1` | 17 | Направление D, вход BIN1 |
| `TB_BIN2` | 16 | Направление D, вход BIN2 |
| `TB_PWMB` | 4 | PWM D |
| `SERVO_PIN` | 27 | Сигнал рулевого сервопривода S |
| `BATT_PIN` | 34 | ADC измерения батареи |
| `SERVO_FEEDBACK_PIN` | 35 | ADC обратной связи позиционного PF Servo |
| `I2C_SDA` | 21 | Общая I²C-шина: OLED + FeatherWing |
| `I2C_SCL` | 22 | Общая I²C-шина: OLED + FeatherWing |

GPIO35 — входной GPIO без внутренней подтяжки. Для обратной связи PF Servo в текущей схеме предусмотрен внешний резистор 10 кОм от GPIO35 к GND. ADC настраивается с `ADC_11db`, измерение выполняется через `analogReadMilliVolts()`.

GPIO4 используется как STBY, поэтому его уровень при старте и внешние соединения нужно учитывать при проверке загрузки ESP32. GPIO34 и GPIO35 являются входами ADC и не могут использоваться как выходы.

## 3. FeatherWing и PCA9685

Параметры backend из `i2c_motor_backend.cpp`:

| Параметр | Значение |
|---|---|
| I²C-адрес FeatherWing/PCA9685 | `0x60` |
| Частота PWM | 1600 Гц |
| Логические каналы | A, B, E, F |
| Физические моторные выходы | M1, M2, M3, M4 |
| Библиотека | Adafruit Motor Shield V2 |

Соответствие выходных каналов PCA9685 по схеме Adafruit Motor Shield V2:

| Мотор | PWM | IN1 | IN2 | Выход |
|---|---:|---:|---:|---|
| A | CH8 | CH10 | CH9 | M1 |
| B | CH13 | CH11 | CH12 | M2 |
| E | CH2 | CH4 | CH3 | M3 |
| F | CH7 | CH5 | CH6 | M4 |

PCA9685 и OLED используют общую шину `Wire`. OLED инициализируется по адресу `0x3C`. Для совместного доступа к I²C backend предоставляет mutex-функции `i2cMotorBackendLockSharedI2c()` и `i2cMotorBackendUnlockSharedI2c()`.

Backend READY означает, что инициализация библиотеки прошла успешно. Это не гарантирует успешность каждой последующей I²C-транзакции: библиотека Adafruit не возвращает статус каждой записи. В диагностической версии после команд выполняется чтение регистров PCA9685, чтобы проверить фактическое содержимое регистров.

Для частоты 1600 Гц значение регистра PCA9685 PRESCALE около `0x03` ожидаемо и согласуется с настройкой частоты. Само по себе это значение не является признаком неисправности.

### Последняя аппаратная диагностика FeatherWing

На 2026-11-01 пользователь предоставил лог, в котором:

- Adafruit backend успешно инициализировался по адресу `0x60`;
- PCA9685 возвращал читаемые MODE1/MODE2/PRESCALE;
- PWM CH8 менялся в соответствии с командами скорости M1;
- IN1/IN2 соответствовали команде движения вперёд и сбрасывались при RELEASE;
- мотор начал работать во время измерений щупами мультиметра и продолжил работать после нескольких циклов выключения/включения питания.

**Причина первоначального отказа не установлена.** Возможны контакт, пайка или соединение, но это пока гипотеза. Не объявлять модуль окончательно исправным и не греть микросхемы без локализации дефекта. На момент последнего сообщения пользователь решил отложить дальнейшую диагностику FeatherWing.

## 4. Управление моторами

Реализация находится в `motor_control.cpp`.

- Каналы A/B/E/F передаются в `i2cMotorBackendSetMotor()` со знаковой скоростью от −100 до 100.
- Каналы C/D управляются напрямую через TB6612FNG: направление выставляется на GPIO, скорость — через LEDC.
- Для прямых каналов используется PWM 5 кГц, разрешение 8 бит; duty ограничивается значением 254, чтобы не использовать проблемную граничную точку 255.
- STBY отдельного TB6612FNG включается, когда C или D ненулевые; FeatherWing от этого STBY не зависит.
- `stopAll()` отменяет позиционирование PF Servo, останавливает FeatherWing, сбрасывает C/D, выключает имитацию ДВС и возвращает рулевой сервопривод в центр.

### Режимы модели

В `motor_control.h` определены:

- `MODE_TANK = 0`;
- `MODE_CAR = 1`.

Других режимов в текущем enum нет.

### Режимы моторных каналов

- A, B, D, E, F: `0` — управление слайдером, `1` — кнопочное управление.
- C жёстко закреплён за позиционным PF Servo: `motorModeC = 2`. Старое значение `modeC` из NVS игнорируется.
- Реверс A/B/D/E/F хранится в NVS. Канал C управляется внутренним позиционным регулятором и не является обычным слайдерным каналом.

### Имитация ДВС

В режиме `MODE_CAR` при включённой имитации ДВС канал B рассчитывается от значения A:

`aux = round(33 + 67 × abs(A) / 100)`

При выключении имитации B получает RELEASE/нулевую команду. Ручное управление B блокируется, пока имитация активна.

## 5. Позиционный PF Servo — текущая реализация

Основная логика находится в `positional_servo.cpp/.h`; команда и настройки обрабатываются в `web_control.cpp`, параметры сохраняются в `preferences_manager.cpp`.

### Подключение и измерение

- Сигнал обратной связи: GPIO35.
- Внешняя подтяжка: 10 кОм между GPIO35 и GND.
- Режим ADC: `ADC_11db`.
- Измерение: `analogReadMilliVolts()`.
- Частота опроса контроллера: каждые 10 мс.
- Фильтр: IIR, `filtered = (3 × previous + raw) / 4`.

Обрыв цепи при внешней подтяжке вниз должен давать значение около 0 В. Короткое замыкание на питание должно вывести измерение за рабочий диапазон. Допустимым для работы контроллер считает диапазон 250–2200 мВ; три последовательных невалидных чтения переводят привод в Fault.

### Калибровочные цели в коде

| Цель | Напряжение |
|---|---:|
| Правое положение | 545 мВ |
| Центральное положение | 816 мВ |
| Левое положение | 1635 мВ |

Эти значения внесены как стартовая калибровка по измерениям существующего механизма. Их точность и повторяемость ещё нужно сверить по фактическим показаниям ADC на собранной модели.

Допуск остановки — ±45 мВ от целевого значения. Промежуточные контакты не являются целями и не должны останавливать движение.

### Зоны индикации

Границы зон в коде: 635, 780, 990 и 1375 мВ. Дополнительный гистерезис переключения зон — 25 мВ.

| Код зоны | Название | Номинальный интервал |
|---:|---|---:|
| 0 | Правое положение | 500–634 мВ |
| 1 | Переход к центру | 635–779 мВ |
| 2 | Центр | 780–989 мВ |
| 3 | Переход к левому | 990–1374 мВ |
| 4 | Левое положение | 1375–1850 мВ |
| 5 | Неизвестно / вне диапазона | ниже 500 или выше 1850 мВ |

Зоны предназначены для индикации состояния в GUI. Они не заменяют целевые напряжения и условие остановки.

### Скорость и профиль движения

- Пользовательская настройка: 10–100%.
- Значение по умолчанию: 50%.
- Настройка сохраняется в NVS по ключу `pfspd`.
- Базовый предел PWM в коде: 70; пользовательские 100% соответствуют этому пределу.
- При приближении к цели на 150 мВ скорость уменьшается до 50% от установленного ограничения.
- Набор скорости плавный: шаг 5 единиц каждые 20 мс, примерно 280 мс до установленного предела.
- Изменение настройки во время движения применяется сразу; при снижении лимита текущая скорость немедленно ограничивается.

### Реверс, тайм-ауты и состояния

Состояния: `Idle`, `Moving`, `WaitingForDirectionChange`, `Fault`.

При смене направления H-мост сначала отключается, затем выдерживается deadtime 30 мс. Контроллер отслеживает прогресс: изменение обратной связи не менее чем на 30 мВ обновляет таймер прогресса. Fault устанавливается при отсутствии прогресса 1200 мс или при общем тайм-ауте перемещения 3000 мс. В Fault мотор останавливается.

### Команды PF Servo

| Назначение | WebSocket JSON |
|---|---|
| Правое положение | `{"posC":"right"}` |
| Центр | `{"posC":"center"}` |
| Левое положение | `{"posC":"left"}` |
| Ограничение скорости | `{"pfSpeed":50}` |

`posC` принимает только строки `left`, `center`, `right`. Канал C не принимает обычную команду `{"ch":"C","val":...}`, когда включён позиционный режим.

### Что осталось проверить на механизме

1. Снять реальные значения GPIO35 в правом, центральном и левом положениях.
2. Сопоставить их с 545/816/1635 мВ и при необходимости скорректировать цели.
3. Проверить попадание в цель с допуском 45 мВ и повторяемость после нескольких перемещений.
4. Подобрать скорость и оценить торможение в окне 150 мВ.
5. Проверить, что промежуточные контакты не останавливают привод.
6. Проверить защиту от обрыва обратной связи и заклинивания без риска для механики.

## 6. Рулевой сервопривод S

Реализация находится в `steering_control.cpp`.

| Параметр | Значение |
|---|---:|
| GPIO сигнала | 27 |
| Частота | 50 Гц |
| Центр по умолчанию | 1500 мкс |
| Максимальный угол по умолчанию | 45° |
| Диапазон настройки максимального угла | 5–135° |
| Диапазон центра в NVS | 1250–1750 мкс |
| Диапазон выходного импульса | 500–2500 мкс |

Настройки сохраняются в NVS. Формула использует масштаб 1000 мкс на 180°:

`pulse_us = center_us + (value / 100) × max_angle_deg × (1000 / 180)`

Фактический угол зависит от конкретного сервопривода и механики. Питание серво должно соответствовать его требованиям и не должно браться с GPIO.

## 7. Питание и мониторинг батареи

Реализация находится в `battery_monitor.cpp`.

- ADC: GPIO34.
- Измерение: восемь чтений `analogRead()` с усреднением.
- Физический делитель, описанный в коде: Rверх 100 кОм, Rниз 2×20 кОм последовательно (40 кОм).
- `BATT_DIVIDER_FACTOR = 0.2857`.
- Текущий полевой коэффициент: `BATT_CALIBRATION_FACTOR = 1.0733`.
- Комментарий к коэффициенту фиксирует измерительную пару: 7,50 В по прошивке и 8,05 В по мультиметру.
- Для полевой калибровки меняется только `BATT_CALIBRATION_FACTOR`, если физические номиналы делителя не менялись.

Уровень заряда рассчитывается линейной интерполяцией между точками:

| Напряжение | Заряд |
|---:|---:|
| 6,0 В | 0% |
| 6,8 В | 10% |
| 7,0 В | 25% |
| 7,4 В | 50% |
| 7,8 В | 75% |
| 8,2 В | 100% |

Порог низкого напряжения — ниже 6,0 В. Процент заряда обновляется после нахождения модели в покое 400 мс. Значение ниже 0,5 В трактуется как отключённая батарея.

Это программная модель индикации, а не универсальная оценка остаточной ёмкости любого аккумулятора. Проверяй тип и допустимые напряжения установленной батареи.

## 8. Web GUI, HTTP и WebSocket

Исходник интерфейса — `lego_technic_esp32/web_page.cpp`. Сгенерированная автономная страница `index.html` обновляется инструментами из `tools/`; не редактируй производный HTML отдельно от исходника.

### HTTP-маршруты

| Путь | Назначение |
|---|---|
| `/` | Встроенный Web GUI |
| `/ws` | WebSocket управления и телеметрии |
| `/logs` | JSON-выгрузка диагностического журнала |
| `/update` | ElegantOTA |

Маршрут `/calib` отключён и текущим GUI не используется.

### Основные WebSocket-команды

| Назначение | Формат |
|---|---|
| Канал A–F и рулевой S | `{"ch":"A","val":75}` |
| Heartbeat с текущими значениями A–F/S | `{"hb":1,"A":0,"B":0,"C":0,"D":0,"E":0,"F":0,"S":0}` |
| Режим | `{"mode":0}` или `{"mode":1}` |
| Центр руля | `{"trim":15}` |
| Максимальный угол руля | `{"maxdeg":45}` |
| Реверс каналов | `{"revA":1}` и аналогично B/C/D/E/F |
| Логическое состояние света | `{"ledF":1}`, `{"ledR":1}` |
| Имитация ДВС | `{"eng":1}` |
| Настройка скорости PF Servo | `{"pfSpeed":50}` |
| Позиция PF Servo | `{"posC":"left"}`, `center`, `right` |
| Сброс настроек | `{"reset":1}` |
| OLED вкл./выкл. до перезагрузки | `{"oled":1}` / `{"oled":0}` |
| Конфигурация канала | `{"cfgA":0}`, аналогично B/D/E/F |

Heartbeat должен содержать все семь текущих значений A/B/C/D/E/F/S и маркер `hb=1`. Он повторно применяет актуальные значения каналов, а не только обновляет таймер. При позиционном режиме C значение C из heartbeat не управляет PF Servo.

### Телеметрия

Статус содержит, среди прочего:

- батарея: `v`, `p`, `lb`;
- Wi-Fi: `r`, число клиентов WebSocket `c` и точек доступа `sta`;
- режим и состояние каналов: `m`, `ra`–`rf`, `cfgA`–`cfgF`;
- свет и имитация: `lf`, `lr`, `es`;
- руль: `tr`, `md`;
- PF Servo: `pfstate`, `pfmv`, `pftarget`, `pfhas`, `pfvalid`, `pfdone`, `pfs`, `pfzone`;
- ресурсы и время: `up`, `heap`, `minh`, `oled`.

Телеметрия отправляется примерно каждые 100 мс подключённым WebSocket-клиентам. Измерение обратной связи PF Servo выполняется отдельным циклом 10 мс; чтение статуса не инициирует новое измерение.

### Диагностический журнал

В прошивке есть кольцевой буфер на 64 строки, длина строки до 127 символов. Лог также выводится в Serial на 115200 бод. HTTP endpoint:

`http://<адрес-ESP32>/logs`

Для получения новых строк можно передать последний полученный ID:

`/logs?after=<id>`

Endpoint возвращает JSON с `latest` и массивом `lines`. Буфер ограничен и старые строки перезаписываются. Это API для диагностики; наличие отдельной кнопки копирования в GUI не подразумевается.

## 9. Безопасность и watchdog

`CMD_TIMEOUT_MS = 500` мс. GUI регулярно отправляет heartbeat с текущими значениями всех каналов. Если в течение 500 мс не поступает корректный пакет управления/heartbeat, loop проверяет активные выходы и вызывает `stopAll()`, если они включены.

При смене режима вызывается `stopAll()`. При сбросе настроек очищается NVS, загружаются значения по умолчанию и останавливаются выходы.

Программный watchdog не заменяет аппаратный выключатель питания и не гарантирует безопасную остановку при отказе I²C, зависании драйвера или аппаратном коротком замыкании. Эти сценарии требуют отдельных испытаний.

## 11. Проверки и ограничения

Разделяй три независимых вида подтверждения:

1. **Проверка кода:** чтение исходников, статические проверки и тесты.
2. **Проверка сборки/CI:** успешная компиляция в реально запущенном workflow.
3. **Аппаратная проверка:** испытания конкретной платы, проводки, питания и механики.

Успех одного уровня не доказывает успех другого. Актуальные workflow и правила работы смотри в [AI_TEAM_WORKFLOW.md](AI_TEAM_WORKFLOW.md) и [AGENTS.md](../AGENTS.md). Перед изменением прошивки проверяй актуальные ветки, PR и SHA main.
