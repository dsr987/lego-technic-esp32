## Реальная архитектура main

ESP32-WROOM-32 управляет шестью моторными каналами и рулевым сервоприводом.

| Канал | Драйвер | Физическое назначение |
|---|---|---|
| A | Adafruit Motor FeatherWing V2 / M1 | DC-мотор |
| B | Adafruit Motor FeatherWing V2 / M2 | DC-мотор или имитация ДВС |
| C | Отдельный TB6612FNG, мост A | Модифицированный позиционный PF Servo |
| D | Отдельный TB6612FNG, мост B | DC-мотор |
| E | Adafruit Motor FeatherWing V2 / M3 | DC-мотор |
| F | Adafruit Motor FeatherWing V2 / M4 | DC-мотор |
| S | ESP32 GPIO27 / ESP32Servo | Рулевой сервопривод |

FeatherWing управляется через PCA9685 по I²C, адрес 0x60, частота PWM 1600 Гц. OLED SSD1306 находится на той же I²C-шине, адрес 0x3C. Отдельный TB6612FNG управляет C/D.

### GPIO из hardware_config.h

| GPIO | Назначение |
|---:|---|
| 25 | STBY отдельного TB6612FNG |
| 18, 19, 23 | C: AIN1, AIN2, PWMA |
| 17, 16, 4 | D: BIN1, BIN2, PWMB |
| 27 | Сигнал рулевого сервопривода |
| 34 | ADC батареи |
| 35 | ADC обратной связи PF Servo |
| 21, 22 | I²C SDA/SCL |

Для GPIO35 предусмотрена внешняя подтяжка 10 кОм к GND. GPIO35 — вход без внутренней подтяжки.

## PF Servo: что уже реализовано

Файлы: `lego_technic_esp32/positional_servo.cpp/.h`, `web_control.cpp`, `preferences_manager.cpp`, `web_page.cpp`.

- Канал C закреплён за позиционным PF Servo; обычное слайдерное управление C отключено.
- Обратная связь читается с GPIO35 в милливолтах каждые 10 мс.
- Входной сигнал фильтруется IIR-фильтром.
- Три цели: right, center, left.
- Текущие целевые значения: right 545 мВ, center 816 мВ, left 1635 мВ.
- Допуск остановки: ±45 мВ.
- Промежуточные контакты не являются целями и не должны останавливать движение.
- Пользовательская скорость 10–100%, по умолчанию 50%, сохраняется в NVS (`pfspd`).
- 100% настройки соответствует базовому PWM-пределу 70.
- В окне 150 мВ до цели скорость снижается до 50% от установленного лимита.
- Разгон плавный: +5 PWM каждые 20 мс.
- При смене направления мост выключается на 30 мс.
- Fault: невалидная обратная связь (три последовательных чтения), отсутствие прогресса 1200 мс или общий тайм-аут 3000 мс.
- Зоны GUI: right, right-to-center, center, center-to-left, left, unknown; границы 635/780/990/1375 мВ, гистерезис 25 мВ.

Целевые значения и границы — программная стартовая калибровка по прежним измерениям. Их ещё нужно подтвердить на текущем механизме и по фактическим показаниям ADC.

## Текущая задача: калибровка PF Servo

Продолжить с проверки уже реализованного регулятора, не переписывая его без необходимости.

Порядок:

1. Открыть веб-пульт и проверить отображаемые `pfmv` и `pfzone`.
2. Перевести механизм в правое положение, записать стабильное напряжение.
3. Повторить для центра и левого положения.
4. Сравнить измерения с 545/816/1635 мВ.
5. Проверить точность остановки, повторяемость и отсутствие остановки на промежуточных контактах.
6. Подобрать скорость и оценить торможение в диапазоне 150 мВ до цели.
7. Только после результатов решать, нужно ли менять целевые напряжения, допуск или профиль движения.

При сообщении результатов фиксировать напряжения в мВ, выбранную скорость, направление движения и достигнутое положение. Не менять несколько параметров одновременно.

## Другие актуальные аппаратные параметры

### Батарея

- GPIO34.
- Делитель по исходнику: Rверх 100 кОм, Rниз 40 кОм (2×20 кОм).
- `BATT_DIVIDER_FACTOR = 0.2857`.
- `BATT_CALIBRATION_FACTOR = 1.0733`.
- Комментарий к поправке: 7,50 В по прошивке против 8,05 В по мультиметру.
- Не менять физический коэффициент без изменения резисторов.

### Рулевое управление S

- GPIO27, 50 Гц.
- Центр 1500 мкс по умолчанию.
- Максимальный угол 45° по умолчанию, диапазон настройки 5–135°.
- Импульс ограничен 500–2500 мкс.
- Центр и угол сохраняются в NVS.

### Связь и интерфейс

- Wi-Fi AP, Web GUI, WebSocket, ElegantOTA.
- HTTP: `/`, `/ws`, `/logs`, `/update`.
- Watchdog команд: 500 мс.
- Heartbeat передаёт актуальные значения A/B/C/D/E/F/S.
- Serial: 115200 бод.
- Кольцевой лог: 64 строки; endpoint `/logs?after=<id>` отдаёт JSON с новыми строками.
- Физическое управление передним/задним светом пока не реализовано; `ledF`/`ledR` сохраняют логическое состояние для GUI.
