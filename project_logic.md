## Логика и техническая архитектура проекта LEGO Technic ESP32

Данный документ является исчерпывающей технической спецификацией прошивки. Он описывает внутренние механизмы, протоколы передачи данных, математику управления и требования к безопасности[cite: 13].

---

## 1. Архитектура передачи данных

Управление моделью осуществляется по следующему сквозному каналу:


```

[ Смартфон / Браузер ]
│
(Wi-Fi Access Point: 192.168.4.1)
│
[ AsyncWebServer ]
│
(WebSocket /ws)
│
[ JSON Parser / Command Router ]
│
┌──────┴────────────────────────┐
▼                               ▼
[ Драйвер TB6612 ]         [ Сервопривод PWM ]
(Моторы A и B)             (Канал руля S)

```

1. ESP32 поднимает точку доступа Wi-Fi (`SSID: LegoTechnic`) и раздает IP по DHCP[cite: 13].
2. Браузер запрашивает монолитную веб-страницу `/`, содержащую HTML/CSS/JS[cite: 13].
3. После загрузки JS открывает полнодуплексное WebSocket-соединение по адресу `ws://192.168.4.1/ws`[cite: 12, 13].
4. Управляющие воздействия и команды калибровки передаются в виде легких JSON-пакетов[cite: 13].

## 2. Распределение ресурсов микроконтроллера

### 2.1. Назначение GPIO
| GPIO | Модуль | Описание |
|---|---|---|
| **4** | TB6612 | `STBY` (Активация драйвера, HIGH = активен)[cite: 13] |
| **16 / 17** | TB6612 | `AIN1` / `AIN2` (Направление мотора A)[cite: 13] |
| **18** | TB6612 | `PWMA` (ШИМ скорость мотора A)[cite: 13] |
| **19 / 21** | TB6612 | `BIN1` / `BIN2` (Направление мотора B)[cite: 13] |
| **22** | TB6612 | `PWMB` (ШИМ скорость мотора B)[cite: 13] |
| **27** | Servo | Сигнальный выход управления сервоприводом[cite: 13] |
| **25 / 26** | OLED | Программный/Аппаратный I2C (`SDA` / `SCL`)[cite: 10, 11, 13] |
| **34** | ADC | Вход АЦП (Замер напряжения аккумулятора)[cite: 13] |

### 2.2. Изоляция ШИМ (LEDC Channels)
Для предотвращения аппаратного конфликта библиотек `ESP32Servo` и системного ШИМ ESP32, таймеры разведены:
- **Мотор A:** аппаратный канал `LEDC_CH_A = 4`[cite: 10, 11, 13].
- **Мотор B:** аппаратный канал `LEDC_CH_B = 5`[cite: 10, 11, 13].
- **Параметры ШИМ:** Частота $5\text{ кГц}$, разрешение $8\text{ бит}$ (диапазон значений $0..255$)[cite: 13].

## 3. Режимы работы и логика моторов

Система поддерживает два режима, переключаемых «на лету»[cite: 12, 13]:

```cpp
enum ControlMode {
    MODE_TANK = 0, // Танковый режим
    MODE_CAR  = 1  // Классический авто-режим
};

```

### 3.1. Танковый режим (`MODE_TANK = 0`)

* **Канал A:** Управляет левым бортом (значение от `-100` до `+100`).


* **Канал B:** Управляет правым бортом (значение от `-100` до `+100`).


* **Канал S:** Инактивирован (сервопривод удерживается в центральном положении).



### 3.2. Классический режим (`MODE_CAR = 1`)

* **Канал A:** Основной привод модели (вперед / назад).


* **Канал B:** Независимый вспомогательный мотор (лебедка, подъемник).


* **Канал S:** Рулевой сервопривод.



### 3.3. Функция управления `setMotor()`

Приём значений $val \in [-100..100]$ транслируется в аппаратный ШИМ по алгоритму:

1. Масштабирование: $PWM = \frac{\vert{}val\vert{} \times 255}{100}$.


2. Установка направления (`IN1`, `IN2`):
* $val > 0$: `IN1 = HIGH`, `IN2 = LOW` (Вперед)


* $val < 0$: `IN1 = LOW`, `IN2 = HIGH` (Назад)


* $val = 0$: `IN1 = LOW`, `IN2 = LOW` (Торможение / Стоп)

## 4. Математика сервопривода и калибровка

Сервопривод работает на частоте $50\text{ Гц}$ и управляется напрямую шириной импульса в микросекундах ($us$).

### Формула вычисления импульса

Для управляющего значения $val \in [-100..100]$ расчёт ширины импульса $T_{us}$ выполняется по формуле:

$$T_{us} = T_{center} + \left( \frac{val}{100} \times MaxDeg \times \frac{1000}{180} \right)$$

Где:

* $T_{center} = 1500\text{ мкс} + Trim$ (Центральная точка с учетом триммера).


* $Trim \in [-400..+400]\text{ мкс}$ — аппаратное смещение центра.


* $MaxDeg \in [5..90]^\circ$ — максимальный угол отклонения руля.


* Итоговое значение жестко ограничивается защитным диапазоном: $T_{us} \in [500..2500]\text{ мкс}$.

## 5. Протокол WebSocket и HTTP API

### 5.1. Управляющие WebSocket-команды (JSON)

* **Управление каналом:**
```json
{"ch": "A", "val": 75}

```


`ch`: `"A"` (мотор A), `"B"` (мотор B), `"S"` (серво).
`val`: integer от `-100` до `100`.


* **Смена режима:**
```json
{"mode": 1}

```


При смене режима немедленно вызывается `stopAll()`, после чего новый режим сохраняется в `Preferences`.


* **Калибровка триммера:**
```json
{"trim": 15}

```


Задает смещение центра $Trim$ в микросекундах.


* **Калибровка угла:**
```json
{"maxdeg": 35}

```


Задает максимальный угол хода руля $MaxDeg$ в градусах.



### 5.2. HTTP Endpoints

* `GET /` — отдаёт вшитый HTML/JS интерфейс.


* `GET /calib` — возвращает текущие параметры калибровки в JSON:


```json
{"trim": 15, "maxdeg": 35}

```


* `GET /update` — интерфейс авторизации и загрузки OTA-прошивки.

## 6. Архитектура безопасности (Safety Layer)

Для предотвращения неконтролируемого движения модели при сбоях связи реализована двухуровневая система аварийной остановки:

```
[ Браузер JS ] ──(Heartbeat каждые 150 мс)──> [ ESP32 Watchdog ]
                                                     │
                                           (Прошло > 500 мс?)
                                                     │
                                                     ▼
                                                [ stopAll() ]

```

1. **JS Heartbeat:** Даже если слайдер в интерфейсе неподвижен, скрипт каждые $150\text{ мс}$ отправляет текущие значения слайдеров для сброса таймера активности.


2. **ESP32 Watchdog:** Если от браузера не поступает ни одного валидного пакета в течение $CMD\_TIMEOUT\_MS = 500\text{ мс}$, автоматически активируется функция `stopAll()`.


3. **Функция `stopAll()`:** Единая точка безопасности. Обнуляет ШИМ моторов A и B, возвращает сервопривод в центр ($T_{center}$) и сбрасывает внутренние регистры состояний.

## 7. Мониторинг аккумулятора и АЦП

Питание измеряется через делитель напряжений $R_1 = 100\text{ кОм}$, $R_2 = 39\text{ кОм}$ на входе GPIO34.

### Алгоритм обработки:

1. Выполняется $8$ последовательных замеров АЦП с усреднением для подавления импульсных шумов.


2. Пересчет в реальное напряжение по калиброванному коэффициенту:

$$V_{batt} = ADC_{avg} \times BATT\_DIVIDER\_FACTOR \quad (BATT\_DIVIDER\_FACTOR = 0.2680)$$



3. Таблица ступенчатой градации заряда для 2S Li-Ion аккумулятора:


* $\ge 8.2\text{ В} \to 100\%$

* $\ge 7.8\text{ В} \to 75\%$

* $\ge 7.4\text{ В} \to 50\%$

* $\ge 7.0\text{ В} \to 25\%$

* $\ge 6.8\text{ В} \to 10\%$

* $< 6.8\text{ В} \to 0\%$

## 8. Энергонезависимая память (NVS Preferences)

Все пользовательские настройки сохраняются во встроенную флеш-память ESP32 через библиотеку `Preferences` (пространство имен: `"cfg"`):

| Ключ | Тип | Описание |
| --- | --- | --- |
| `mode` | `uint8_t` | Сохраненный режим управления (`0` или `1`)

 |
| `steer_c` | `int32_t` | Значение калибровки центра $Trim$<br> |
| `steer_a` | `int32_t` | Значение калибровки угла $MaxDeg$<br> |

## 9. Правила проведения рефакторинга

При внесении изменений в код строго соблюдайте следующие критические зависимости:

1. **Не меняйте назначение GPIO** без одновременного перерасчета принципиальной схемы и проверки загрузочных пинов ESP32.


2. **Не изменяйте номера LEDC каналов (4 и 5)** во избежание пересечений с таймерами библиотеки `ESP32Servo`.


3. **Не меняйте имена ключей `Preferences**`, так как это приведет к сбросу калибровок у существующих пользователей.


4. **Сохраняйте задержку Watchdog:** Отношение интервала Heartbeat ($150\text{ мс}$) к таймауту Watchdog ($500\text{ мс}$) должно составлять минимум $1:3$ во избежание ложных срабатываний при задержках Wi-Fi.
