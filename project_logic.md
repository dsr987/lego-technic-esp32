# Логика и техническая архитектура проекта LEGO Technic ESP32

Техническая спецификация прошивки: внутренние механизмы, протоколы, математика управления, требования к безопасности. Соответствует версии **0.0.6**.

---

## 1. Архитектура передачи данных

```
[ Смартфон / Браузер ]
          │
 (Wi-Fi точка доступа: 192.168.4.1)
          │
   [ AsyncWebServer ]
          │
    (WebSocket /ws)
          │
[ JSON-парсер / роутер команд ]
          │
   ┌──────┴────────────────┐
   ▼                       ▼
[ Драйвер TB6612 ]   [ Сервопривод, ШИМ ]
 (моторы A и B)        (канал руля S)
```

1. ESP32 поднимает точку доступа (SSID по умолчанию `LegoTechnic`), IP-адреса выдаются по DHCP.
2. Браузер запрашивает страницу `/` (HTML, CSS и JS в одном файле, вшитом в прошивку).
3. JS открывает WebSocket `ws://192.168.4.1/ws`.
4. Команды управления и калибровки передаются компактными JSON-пакетами.

## 2. Ресурсы микроконтроллера

### 2.1. Назначение GPIO

| GPIO | Модуль | Описание |
| --- | --- | --- |
| **4** | TB6612 | `STBY`: активация драйвера (HIGH = активен) |
| **16 / 17** | TB6612 | `AIN1` / `AIN2`: направление мотора A |
| **18** | TB6612 | `PWMA`: скорость мотора A |
| **19 / 21** | TB6612 | `BIN1` / `BIN2`: направление мотора B |
| **22** | TB6612 | `PWMB`: скорость мотора B |
| **27** | Servo | Сигнал сервопривода |
| **25 / 26** | OLED | I2C `SDA` / `SCL` (пины назначены программно) |
| **34** | ADC | Вход АЦП, замер напряжения батареи (только вход) |

### 2.2. Каналы ШИМ (LEDC)

- **Мотор A:** канал `LEDC_CH_A = 4`.
- **Мотор B:** канал `LEDC_CH_B = 5`.
- **Параметры:** частота 5 кГц, разрешение 8 бит (значения 0..255).

Каналы 4 и 5 выбраны, чтобы не пересекаться с каналом, который библиотека `ESP32Servo` занимает сама (по умолчанию она ищет свободный канал, начиная с 0). Конфликт каналов 0/1 был вероятной причиной дребезга сервы при газе. Это гипотеза, подтверждённая практикой: после переноса на 4/5 дребезг исчез.

## 3. Режимы работы и логика моторов

```cpp
enum Mode { MODE_TANK = 0, MODE_CAR = 1 };
```

Режимы переключаются на лету.

### 3.1. Танковый режим (`MODE_TANK`)

- **Канал A:** левый борт (-100..100).
- **Канал B:** правый борт (-100..100).
- **Канал S:** игнорируется, сервопривод остаётся в центре.

### 3.2. Классический режим (`MODE_CAR`)

- **Канал A:** основной привод (вперёд и назад).
- **Канал B:** вспомогательный мотор (лебёдка, подъёмник).
- **Канал S:** руль (сервопривод).

### 3.3. Функция `setMotor()`

Значение `val` от -100 до 100 преобразуется в ШИМ и направление:

```
duty = |val| * 255 / 100
val > 0:  IN1 = HIGH, IN2 = LOW   (вперёд)
val < 0:  IN1 = LOW,  IN2 = HIGH  (назад)
val = 0:  IN1 = LOW,  IN2 = LOW   (Stop: выходы отключены, мотор идёт выбегом)
```

При нуле это **не торможение**. Режим торможения у TB6612 включается комбинацией `IN1 = IN2 = HIGH`, в прошивке он сейчас не используется. Механизмы, которые должны держать груз (лебёдка, кран), при нулевой скорости груз не удержат.

## 4. Сервопривод и калибровка

Сервопривод работает на 50 Гц, управляется шириной импульса в микросекундах.

```
T_us = T_center + (val / 100) * MaxDeg * (1000 / 180)

T_center = 1500 + Trim
Trim     : -400 .. +400 мкс
MaxDeg   : 5 .. 90 градусов
Итог     : ограничивается диапазоном 500 .. 2500 мкс
```

Множитель `1000 / 180` соответствует стандартной шкале хобби-серв (1000 мкс на 180°).

Для позиционного сервопривода результат означает угол. Для Geekservo 360° (непрерывное вращение) ширина импульса задаёт скорость и направление вращения, а `MaxDeg` фактически ограничивает скорость до механического упора.

## 5. Протокол WebSocket и HTTP

### 5.1. WebSocket-команды (JSON)

- **Управление каналом:** `{"ch": "A", "val": 75}`. Значение `ch`: `"A"` (мотор A), `"B"` (мотор B), `"S"` (серво), `val`: целое от -100 до 100.
- **Смена режима:** `{"mode": 1}`. Сразу вызывается `stopAll()`, затем режим сохраняется в `Preferences`.
- **Триммер центра:** `{"trim": 15}` (смещение в мкс, абсолютное значение, не приращение).
- **Максимальный угол:** `{"maxdeg": 35}`.

### 5.2. HTTP-эндпоинты

- `GET /`: вшитая веб-страница.
- `GET /calib`: текущая калибровка, например `{"trim": 15, "maxdeg": 35}`.
- `GET /update`: страница ElegantOTA (требует логин и пароль).
- `POST /ota/upload`: приём файла прошивки (служебный эндпоинт ElegantOTA, требует логин и пароль).

## 6. Безопасность (Safety Layer)

Двухуровневая защита от неконтролируемого движения при сбое связи:

```
[ Браузер JS ] ──(heartbeat каждые 150 мс)──> [ Watchdog на ESP32 ]
                                                     │
                                          (прошло больше 500 мс?)
                                                     │
                                                     ▼
                                                [ stopAll() ]
```

1. **JS heartbeat.** Пока слайдер неподвижен, браузер не генерирует событий, поэтому скрипт каждые 150 мс повторно отправляет текущие значения всех каналов. Без этого watchdog принимал бы удержание слайдера за обрыв связи.
2. **Watchdog на ESP32.** Программная проверка в `loop()`: если с момента последнего валидного пакета (`lastCmdMillis`) прошло больше `CMD_TIMEOUT_MS = 500` мс, вызывается `stopAll()`. Таймер сбрасывается любым разобранным JSON-пакетом, включая `mode`, `trim` и `maxdeg`.
3. **`stopAll()`.** Обнуляет ШИМ моторов A и B, возвращает сервопривод в центр (`T_center`) и сбрасывает внутренние значения каналов.

## 7. Мониторинг батареи

Напряжение измеряется через делитель R1 = 100 кОм, R2 = 39 кОм на GPIO34.

### 7.1. Расчёт напряжения

1. Усредняются 8 замеров АЦП.
2. Отсчёты переводятся в вольты на входе АЦП, затем делятся на калиброванный коэффициент делителя:

```
V_adc  = ADC_avg / 4095 * 3.3
V_batt = V_adc / BATT_DIVIDER_FACTOR        (BATT_DIVIDER_FACTOR = 0.2680)
```

Номинальный коэффициент делителя 39/139 = 0.2806, но реальные резисторы дают разброс, поэтому коэффициент откалиброван по мультиметру. Пересчёт при изменениях в схеме:

```
новый_коэффициент = старый_коэффициент * (показание_кода / показание_мультиметра)
```

АЦП ESP32 нелинеен у краёв диапазона, при калибровке лучше опираться на рабочие значения батареи.

### 7.2. Ступени заряда (2S Li-Ion)

| Напряжение | Заряд |
| --- | --- |
| от 8.2 В | 100 % |
| от 7.8 В | 75 % |
| от 7.4 В | 50 % |
| от 7.0 В | 25 % |
| от 6.8 В | 10 % |
| ниже 6.8 В | 0 % |

### 7.3. Предупреждение LOW BATTERY

- Порог `LOW_BATTERY_THRESHOLD_V = 6.0` В (3.0 В на банку 18650).
- Если напряжение ниже `BATTERY_DISCONNECTED_V = 0.5` В, батарея считается неподключённой (отладка по USB), предупреждение не показывается.
- Антидребезг: экран обновляется раз в секунду, тревога включается после 3 замеров подряд ниже порога и выключается только выше 6.3 В. Просадка под нагрузкой не даёт ложных срабатываний.

## 8. OLED-индикация

Обновляется раз в секунду:

- крупно (размер 2): режим (`TANK` или `CAR`) и заряд в процентах;
- мелко: напряжение в вольтах и число подключённых клиентов;
- справа: иконка текущего режима, нарисованная примитивами `Adafruit_GFX`;
- при срабатывании LOW BATTERY весь экран занимает предупреждение с напряжением.

## 10. Значения по умолчанию

| Параметр | Значение | Где в коде |
| --- | --- | --- |
| Имя Wi-Fi точки | `LegoTechnic` | `WiFi.softAP(...)`, первый аргумент |
| Пароль Wi-Fi точки | `12345678` | `WiFi.softAP(...)`, второй аргумент (не короче 8 символов) |
| Логин и пароль OTA | `admin` / `admin` | `ElegantOTA.begin(&server, "admin", "admin")` |
| Таймаут watchdog | 500 мс | `CMD_TIMEOUT_MS` |
| Порог LOW BATTERY | 6.0 В | `LOW_BATTERY_THRESHOLD_V` |
| Коэффициент делителя | 0.2680 | `BATT_DIVIDER_FACTOR` |

Оба пароля лежат в открытом репозитории, поэтому при использовании модели вне домашней мастерской их нужно сменить (строки около 655 и 671 в `app.cpp`, надёжнее искать по тексту).

## 11. Правила рефакторинга

При изменениях в коде соблюдайте зависимости:

1. **Не меняйте назначение GPIO** без пересмотра схемы и проверки загрузочных пинов ESP32.
2. **Не меняйте номера LEDC-каналов (4 и 5):** возможен конфликт с каналом, который занимает `ESP32Servo`.
3. **Не переименовывайте ключи `Preferences`:** иначе сбросятся сохранённые настройки.
4. **Сохраняйте соотношение heartbeat и watchdog:** 150 мс к 500 мс, минимум 1:3, чтобы задержки Wi-Fi не вызывали ложных остановок.
5. **Структура файлов:** код лежит в `app.cpp`, его первая строка `#include <Arduino.h>`. `lego_technic_esp32.ino` остаётся пустой заглушкой, а имя папки должно совпадать с именем `.ino`.
6. **Версия ядра и библиотек зафиксирована** (ESP32 core 2.0.9, ESPAsyncWebServer 3.1.0, AsyncTCP 1.1.4). Обновление без проверки может сломать компиляцию.
