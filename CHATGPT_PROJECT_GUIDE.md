## 1. Если пользователь говорит «смотри репо и продолжим»

Не проси заново пересказывать проект. Сначала:

1. Прочитай `AGENTS.md`.
2. Прочитай [`docs/PROJECT_HANDOFF.md`](docs/PROJECT_HANDOFF.md) — это краткий актуальный срез задач, аппаратуры и последних диагностик.
3. Прочитай [`docs/project_logic.md`](docs/project_logic.md) — полная техническая документация.
4. Проверь живое состояние GitHub: SHA `main`, открытые PR, ветки и последние коммиты.
5. Для конкретной задачи открой исходники, указанные в handoff. Не полагайся на старые чаты, сохранённые выжимки или номера PR без проверки.

Документы являются стартовой картой, а не заменой проверки текущего кода.

## 2. Проект

LEGO Technic ESP32 — прошивка ESP32-WROOM-32 с собственной Wi-Fi точкой доступа, браузерным Web GUI, WebSocket, OTA, OLED, мониторингом батареи и шестью моторными каналами.

На срезе 2026-11-01:
- версия прошивки в главном скетче: `0.14.1`;
- актуальный проверенный main: `331412f6f3147468e484a5dc9de3df6489fec7c5`;
- FeatherWing V2 / PCA9685 управляет A/B/E/F через M1–M4;
- отдельный TB6612FNG напрямую от ESP32 управляет C/D;
- канал C закреплён за модифицированным позиционным LEGO PF Servo с обратной связью GPIO35;
- GPIO35 имеет внешнюю подтяжку 10 кОм к GND;
- текущий пользовательский фокус — аппаратная калибровка PF Servo;
- FeatherWing временно отложен: после измерений мотор заработал и пережил несколько циклов питания, но причина первоначальной нестабильности не установлена.

Все эти данные необходимо сверить с GitHub и исходниками при начале нового чата.

## 4. Правила взаимодействия и GitHub

- Отвечай по-русски, если пользователь не переключился на другой язык.
- Если пользователь просит продолжить согласованную работу, переходи к следующему незавершённому шагу; не задавай повторно вопросы, на которые уже есть ответ в handoff или коде.
- Сначала проверь актуальные инструкции, архитектуру, SHA main, ветки, PR и workflow.
- Делай минимальные совместимые изменения. Не смешивай независимые изменения прошивки, GUI, CI и аппаратной схемы.
- Не запускай GitHub Actions вручную без прямого разрешения пользователя.
- Не считай CI обязательным PR-check, если это не подтверждено настройками репозитория.
- Разделяй проверку кода, сборки/CI и реального оборудования.
- Не утверждай, что команда, сборка, тест или аппаратное действие выполнены, если это не подтверждено результатом.
- Для PR используй ровно одну метку `release:*`, раздел `## Changelog`, проверки и отдельный статус аппаратной проверки.
- Источники версии и changelog прошивки — маркеры в `lego_technic_esp32/lego_technic_esp32.ino`; производные документы обновляй предусмотренными инструментами.

## 5. Проверки и инструменты

Сверяй список с `AGENTS.md` и действующими workflow. Из известных инструментов проекта:

```bash
python3 tools/project_auditor.py

python3 tools/test_release_automation.py
python3 tools/test_calibrate_battery.py
node tools/test_battery_warnings.js
```

Не объявляй все перечисленные команды обязательными для каждой задачи. Выбирай проверки по изменённой области. Тестовые скетчи из `test/` могут требовать отдельной ручной сборки.

## 6. Аппаратные оговорки

- Не путай Hardware 1.5 с текущей конфигурацией main.
- В текущем коде A/B/E/F идут через FeatherWing; C/D — через отдельный TB6612FNG.
- FeatherWing backend READY не доказывает успешность каждой I²C-записи.
- GPIO35 — вход ADC без внутренней подтяжки; PF Servo использует внешний резистор 10 кОм к GND.
- Перед испытаниями моторов обеспечивай возможность физически отключить их питание.
- Не грей и не перепаивай микросхемы без локализации аппаратной неисправности.
- Не считай программную защиту гарантией остановки при отказе I²C или драйвера.
- Не объявляй аппаратную функцию проверенной только по успешной компиляции.
